# v0.4.0

API migration release: case listing now uses the Red Hat GraphQL API, replacing the REST v3 filter endpoint that was limited to ~5 cases per response.

## What Changed

### GraphQL Case Listing

The REST v3 `POST /cases/filter` endpoint returns full case objects (~100KB each, with inline comments, bugzillas, and descriptions). Salesforce payload limits meant most queries returned only 4-6 cases regardless of how many matched.

agcm now uses the Red Hat GraphQL API (`https://graphql.redhat.com`) for case listing. GraphQL lets us request only the fields the list view needs (~200 bytes per case), so a single request returns up to 200 cases with cursor-based pagination for more. Individual case detail, comments, and attachments are still fetched via REST v3 when you select a case.

### Full v1/Hydra API Removal

The v1 Solr-backed API was deprecated and its search index had gone stale (returning zero non-closed cases). All remaining v1 code paths have been removed:

- Case search (`agcm search`) now queries via GraphQL instead of Hydra
- Attachment downloads use the v3 presigned-URL flow
- The `postHydra` client method is gone

### v3 Data Model

The Case, Comment, and Attachment structs now match the v3 Salesforce field names and formats:

- **Dates**: New `FlexTime` type handles Salesforce's `2006-01-02T15:04:05.000+0000` format alongside ISO 8601
- **Comments**: HTML comment bodies are converted to plain text via `html2text`; the `CreatedByType` field replaces the old boolean public/private flags
- **Statuses**: v3 uses "In Progress", "Waiting on Customer Action Required", "Needs New Owner", and "Closed" — the filter bar and filter dialog recognize both old and new names
- **Products**: The v3 product field includes the version (e.g., "Red Hat Enterprise Linux 9.8"); the filter uses prefix matching so "Red Hat Enterprise Linux" still works

## Fixes

- Case list now shows all matching cases instead of capping at ~5
- `agcm list accounts` simplified — v3 does not expose account names, so the output shows account numbers only
- `agcm show` displays `CreatedByType` instead of the removed boolean `Public` field
- Export markdown template updated for v3 field names (`caseType`, `accountNumberRef`, `emailAddress`)

## Known Limitations

- **Group and owner filters**: The GraphQL endpoint does not support `groupNumber` or `ownerSSOName` filtering. These filters are silently ignored; a 2-year lookback is applied as a safety scope when no other filters are set.
- **Account names**: The v3 API does not return account names in case responses. The `accounts` command now shows numbers only.
